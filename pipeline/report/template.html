Statistical Comparison — Ag-Specific vs Non-Ag-Specific

Mann-Whitney U test (two-sided). Effect size = rank-biserial r. "Significant?" uses Benjamini-Hochberg FDR correction applied across all comparisons in this table (raw p-value also shown). This is the naive, unmatched comparison — the Non-Ag group is a small, scale-mismatched convenience sample (see the Matched Comparison tab for the confound-controlled version before drawing conclusions from this table alone). MDE, not Achieved Power, is the metric to read for whether a non-significant result reflects a real null or just an underpowered sample — achieved/retrospective power is a near-deterministic function of the p-value already shown (a small observed effect always looks "low power" in retrospect) and is widely regarded as uninformative on its own; it's shown for completeness only. See Hoenig & Heisey (2001), "The Abuse of Power."

Kruskal-Wallis Test across Categories

Non-parametric one-way test. Dunn's post-hoc with Bonferroni correction. * p_adj < 0.05. MDE / Achieved power use Noether's (1987) approximation for Wilcoxon-Mann-Whitney, applied to each Dunn pair at its actual n and Bonferroni-adjusted alpha — indicative at these small category sizes, not exact. Prefer MDE over Achieved Power: retrospective power is a near-deterministic function of the p-value already shown and is widely regarded as uninformative on its own (Hoenig & Heisey 2001).

Joint Regression Model

The Mann-Whitney/Kruskal-Wallis tests above test category and ag-specificity separately. Category and ag_specific overlap in this dataset (some categories have zero non-ag members), so this model fits each outcome on category, ag_specific, and scale (log stars, log contributors) simultaneously via ordinary least squares — each coefficient is the partial effect holding the others fixed. Standard errors use the HC3 heteroskedasticity-robust estimator (not classical/homoskedastic SEs) since GitHub activity and security metrics are essentially guaranteed to be heteroskedastic even after the log1p transforms applied here — coefficients and R² are unaffected by this choice, only the SE/t/p-values are. Check the VIF column before trusting an individual coefficient: VIF > 5 flags collinearity that makes that term's estimate unstable.

Robustness Check — Random-Matching Seed Stability

Secondary check, not the headline result: instead of always pairing each dataset repo with its single closest control (the primary estimate above), this draws k controls at random from the same eligible pool across 1,000 seeds. "Stable" means at least 95% of seeds agreed on the direction of the effect (AgOSS better vs. worse) — i.e. the primary conclusion doesn't depend on always getting the best-available match.

Regression-Adjusted Estimate — Matching Only vs Matching + Regression

The Covariate Balance table above can show log_stars and log_forks staying imbalanced even after matching. This fits outcome ~ treatment + log_stars + log_forks by OLS (HC3 robust SE) on the matched sample — every matched repo plus every control actually selected, the same "after matching" set Covariate Balance itself uses — for each headline metric, and compares the adjusted treatment coefficient to the simple (unadjusted) mean matched-pair difference. Agreement is reported as two separate questions rather than one combined "consistent?" judgment, since collapsing them can hide a sign flip: two estimates can both be individually non-significant (wide CIs that each happen to contain the other's point estimate) while pointing in opposite directions. Same Direction? asks only about the sign of the effect; Significant Under Both? asks whether both methods independently reject the null at p<0.05 / CI excludes zero. Only when both are "Yes" does the conclusion not depend on whether residual size differences are handled by nearest-neighbor averaging or a regression surface.

Unmatched-Repo Sensitivity Analysis

The — unmatched repos above (not affected by the group dropdown, same reasoning as Unmatched Repo Characterization) contribute nothing to the median Δ shown elsewhere on this page. This bounds what would happen to that median if they HAD been matched: for each unmatched repo, "best case" imputes it against the most favorable outcome actually observed among OTHER matched repos' selected controls in the SAME category (worst case uses the least favorable) — an empirically observed value, not a synthetic one. If the median Δ keeps the same sign under both bounds, the conclusion does not depend on how these particular repos would have matched. This reflects whichever repos are actually unmatched at the currently selected k, not a fixed set.
